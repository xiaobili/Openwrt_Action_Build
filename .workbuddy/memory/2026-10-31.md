## OpenWrt_Action_Build 重构（配置化 + 去重）

目标：代码可维护、可配置。方向经确认：抽可复用 workflow、build.conf + 分组清单、保持向后兼容。

### 落地结构
- `config/build.conf`：源码/分支/版本号格式/作者/网口/主题/修复开关的**唯一配置源**，POSIX 赋值。
- `config/feeds.list`：额外 feed 源，由 `diy-feeds.sh` 幂等前置到 `feeds.conf.default`。
- `config/packages/*.list`：插件清单 DSL（`clone` / `sparse` / `purge` / `run`，支持 ` || ` 回退链），四层叠加
  common → `<source>` → `<profile>` → `<source>-<profile>`。
- `lib/{common,config,source,packages,theme,version,fix}.sh`：单一职责库。
- `scripts/diy.sh`：唯一 DIY 引擎（`--profile --source --dry-run --list-profiles`）；
  `diy-full.sh`/`diy-mini.sh` 降为 3 行兼容壳。
- `.github/workflows/build.yml`：workflow_call 复用工作流（matrix=fromJSON(inputs.targets)），
  三个入口 workflow 各 ~46 行，只声明 targets / 发布后缀 / 说明模板。
- `.github/release-notes/*.md` + `scripts/render-template.sh`（envsubst，只替换全大写 `${VAR}`）。
- `scripts/lint.sh` + `Lint.yml`：bash -n、shellcheck、清单 DSL、targets JSON 自检。

### 顺带修掉的真实 bug
1. `diy-mini.sh` 的 `detect_source_type` 用 `log_info` 返回值，ANSI 码污染 `$(...)`，`case` 永不匹配
   → **mini 构建从未执行版本号修补**。现统一在 `lib/source.sh`，日志走 stderr。
2. `$GITHUB_WORKSPACE/files` 先 `rm -rf` 再拷贝，自定义 files 从未生效。
3. LEDE workflow 用 `>` 写 `$GITHUB_ENV`，只有最后一个变量生效。
4. `diy-feeds.sh` 用 `sed '1i'/'2i'`，重复执行会重复插入；改幂等。
5. LEDE 版本号用 `sed "s/${orig_version}/..."`，原值里的 `.` 被当通配符；改整行替换。
6. 删除死代码 `patch/fix_version_backup.sh`。
